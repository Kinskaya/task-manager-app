# Приложение для управления задачами — тестовое задание для Middle Frontend-разработчика


## Технологии

**Обязательно:**
- React: Next.js (App Router) или SPA (Vite / аналог)
- TypeScript
- Storybook

**На ваш выбор:**
- Стилизация и UI-kit
- Валидация форм
- Vitest или Jest

## Данные

Source of truth — не UI-стейт и не `import data.json` в компонент. Чтение и запись через слой данных.

- **Next.js:** RSC / Server Actions / `app/api/*`. Клиентский `fetch` / `useEffect` — только там, где нужен клиентский компонент (тема, инпут, модалка).
- **SPA:** запросы к API (свой бэк, MSW, json-server — на выбор).

## Функциональность приложения

### 1. Авторизация
- Форма входа: email и пароль
- Валидация полей
- Состояние загрузки и отображение ошибки
- Локальные учётные данные для проверки: `admin@example.com` / `Admin123!`

### 2. Списки задач (`/lists`)
Карточка списка отображает:
- Название
- Счётчики задач: new / in progress / done / overdue
- Прогресс-бар
- Цветовой индикатор: красный — есть просроченные задачи, жёлтый — дедлайн в ближайшие 48 часов

Пользователь может:
- Создать новый список
- Переименовать список
- Удалить список
- Искать списки

### 3. Задачи списка (`/lists/[id]`)
Таблица задач: название, статус, приоритет, дедлайн.
Пользователь может:
- Добавить задачу
- Редактировать задачу
- Удалить задачу
- Изменить статус задачи
- Фильтровать по статусу

### 4. Карточка задачи
Модальное окно или отдельная страница `/tasks/[id]`.
Отображается:
- Название
- Описание
- Статус
- Приоритет
- Дедлайн

Сохранение — через слой данных (сервер / API).



## Сортировка задач
1. Незавершённые просроченные — выше всех
2. Чем ближе дедлайн — тем выше
3. Пользовательский приоритет — как tie-breaker
4. Выполненные (`done`) — внизу списка

## Storybook и тесты
- Минимум **5 историй с `play`** (`@storybook/test`): отправка формы логина, валидация, смена статуса
- Юнит-тесты на сортировку и счётчики карточки: **не менее 8**
